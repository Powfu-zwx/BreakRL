# Contributing

Issues and pull requests are welcome: fix errors, improve experiments, add failure modes, or write new chapters.

A [Chinese edition](CONTRIBUTING.zh.md) of this guide is also available.

## Environment

Readers can run any chapter in Colab from the README without this setup. The first code cell of each experiment notebook bootstraps Colab (clone, install extras, `chdir` into the chapter). That cell is generated from `scripts/colab_setup.py` and tagged `remove-cell` so the site does not render it; after changing the helper, run `python scripts/sync_colab_bootstrap.py` and do not hand-edit the cell. `BREAKRL_CHAPTER` is the directory name under `book/notes/`.

Local editing still uses:

```bash
conda create -n rl_env python=3.10
conda activate rl_env
python -m pip install -r requirements.txt
python -m ipykernel install --user --name rl_env --display-name rl_env
python scripts/run_jupyter.py   # Windows certificate-store workaround; otherwise python -m jupyter lab
```

`requirements.txt` keeps lower bounds so Colab resolves current packages. The committed figures and saved outputs were generated with Python 3.10.21, numpy 2.2.6, matplotlib 3.10.9, torch 2.9.0, and gymnasium 1.3.0, on the site toolchain jupyter-book 1.0.4.post1 / myst-nb 1.4.0 / Sphinx 7.4.7; a newer stack can move the last digits of an experiment.

## Chapter layout

Each chapter lives in `book/notes/<chapter>/` and follows this convention:

- one `<chapter>.tex` file and the compiled `<chapter>.pdf`;
- one `<chapter>_experiments.ipynb`;
- three `fig*.pdf` experiment figures generated by the notebook.

That shape is a convention, not a schema. `scripts/check_consistency.py` only checks that every `.tex` has a compiled PDF beside it and that every experiment notebook parses; what a chapter holds beyond that is the author's call.

**Bilingual pair:** every chapter has a Chinese edition (`<chapter>.tex` / `<chapter>.pdf` / `<chapter>_experiments.ipynb`) and an English edition (`<chapter>_en.tex` / `<chapter>_en.pdf` / `<chapter>_experiments_en.ipynb`). English notebooks translate markdown cells only; code and saved outputs must match the Chinese notebook (`scripts/check_consistency.py` enforces this). Register both editions in the English and 中文版 parts of `book/_toc.yml`, in `README.md`, in `README.zh.md`, and in the `book/index.md` / `book/index-zh.md` tables. **If you change Chinese conclusions, numbers, or figures, update the English edition in the same change.**

The site language toggle (`book/_static/lang-toggle.js`) pairs pages by filename. Chapter notebooks pair automatically (`*_experiments` ↔ `*_experiments_en`, and `scripts/check_consistency.py` fails when one edition is missing); the site's own text pages are listed in the toggle's `TEXT_PAGES`, so a new one needs an entry there: `failure-atlas` ↔ `failure-atlas-en`, `index.html` ↔ `index-zh.html`, `offline-rl-text` ↔ `offline-rl-text-en`. The homepage is one language per page (English default).

Chapter text follows [`book/notes/rl_note_template.tex`](../book/notes/rl_note_template.tex): story → formalism → mechanism (three ablation figures) → algorithm → comparison → place in the family → references. Use `[!htbp]` on figure environments. Notebooks use three Figure sections plus a short recap.

A new chapter must also update `book/_toc.yml`, `README.md`, `README.zh.md`, `book/index.md`, `book/index-zh.md`, and any cross-chapter numbering.

## Checks and TeX

```bash
python scripts/check_consistency.py            # same structural check as CI
python scripts/test_colab_setup.py             # Colab bootstrap unit tests
conda run -n tex_env tectonic book/notes/<chapter>/<chapter>.tex   # recompile the PDF after TeX edits
jupyter-book build book                        # rebuild the online book after book changes
```

**Commit TeX and PDF together.** If you change the text without recompiling, the public PDF stays stale.

## Notebooks

- The site renders **saved notebook outputs** and does not re-execute them. After you rerun an experiment, confirm that the numbers still match the text and captions before you commit.
- Rerunning overwrites `fig*.pdf` in the chapter directory. That is intended (figures come from the code), but review the diff.
- Quantitative claims in the text must be backed by notebook output or stdout.

## Failure Atlas

Each entry in [`book/failure-atlas.md`](../book/failure-atlas.md) follows “symptom → mechanism → reproduction → fix.” Submit a new entry with the Failure-mode issue template. Adopted entries should link to the matching chapter experiment.
